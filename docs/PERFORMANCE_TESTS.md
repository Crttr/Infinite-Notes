# План нагрузочных проверок Windows

Используйте отдельный тестовый проект и экспортируйте резервную копию до начала.

| Сценарий | Что записать |
|---|---|
| 100 заметок, 100 связей | время открытия, перемещение, масштабирование |
| 500 заметок, 500 связей | плавность панорамирования, память, длительность сохранения |
| 1000 заметок, 1000 связей | задержки, память, стабильность импорта/экспорта |
| 20 изображений по 5–10 МБ | размер `.inotes`, время открытия, восстановление |
| быстрое переключение A → B → A | отсутствие смешивания данных |
| закрытие сразу после изменения | сохранение последней правки |

Проверяйте в релизной сборке, а не только в `tauri dev`. Для CPU/RAM используйте диспетчер задач; для React — React DevTools Profiler. Не генерируйте тысячу объектов в рабочем проекте.

Уже есть в текущем коде: lazy-загрузка NoteCard, RichText и ImageGallery, индексация узлов через Map, отложенная запись заметок и рёбер (350 мс), разделение чанков Vite. Без замеров менять React Flow нецелесообразно.
